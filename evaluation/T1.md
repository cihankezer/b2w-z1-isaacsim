# T1 standing 6D tracking — first implementation

Protocol: [`TASK_T1.md`](../docs/protocols/TASK_T1.md), `1.0.0-draft.2`.
Task: `RobotLab-Isaac-T1-Standing-Unitree-B2W-Z1-v0`.

This is a no-learning task and scripted evaluator for B2W + Z1. It preserves the
existing RFM tasks/checkpoints. Task files are in
`training/robot_lab_overlay/source/robot_lab/robot_lab/tasks/manager_based/manipulation/standing_ee/`.
The evaluator loads this new package directly from the overlay; no setup/install
or dependency checkout edits are needed for these entrypoints.

## What is implemented

- Nominal flat-ground task; 22 nominal-offset actions with zero wheel velocity
  targets; structured proprioception, measured EE and body-frame goal fields.
- World-fixed goals and simulation-time circles; a C² translation transition
  matches the circle's initial position, velocity and acceleration.
- Separate standing diagnostics, geometric/contact collision checks, tilt/height
  failures, invalid-state handling and normal timeout.
- Per-controller-tick physical-state capture **before automatic reset**.
- Deterministic candidate generation, independent composed-USD FK/6D IK,
  physical-surface narrow-phase checks, whole-circle/transition sampling and full
  rejection logs. Target definitions and asset hashes are checked on loading.
- New run directories containing `steps.csv`, `run_config.yaml`, source copies,
  `targets.json`, `trial_summary.csv`, `aggregate_summary.json` and completion or
  error information. Preparation additionally writes a reference snapshot and
  generation audit. All raw phases remain available; error summaries use only
  steady-state samples from completed nonfailed trials.

Fixed scoring: final 5 s, `(5,10]` of fixed phase. Circle scoring: second revolution,
`(20,40]` of circle phase. Each is a proposed steady-state definition; neither is
claimed to have been specified by the paper. Errors pool eligible controller
ticks, with population SD (`ddof=0`) explicitly named. The paper's printed ± is
not fully defined. Primary orientation is matrix-log Frobenius norm; geodesic
radians are also exported. Success means survival to timeout, not accuracy or
standing compliance. Failed trials remain in the success denominator and are
excluded entirely from error statistics, including samples before a late fall.

## CPU validation

From the repository root, with NumPy, SciPy and pytest already available:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider tests/test_t1.py
```

These tests deliberately import only the pure modules, without Gym, Torch,
Isaac Lab, Docker or a GPU. They exercise reference geometry and continuity,
score boundaries, quaternion conventions, metrics, failed/incomplete/empty trial
statistics, manifest integrity, FK ordering and broad-phase collision bounds.
`tests/test_t1_usd.py` additionally checks invisible/guide collision shapes,
exclusion of visual-only geometry, collider transforms and the actual asset
against the existing USD SDK. These tests require that SDK; ordinary host Python
skips that module. The SDK checks are CPU-only and do not launch SimulationApp.
`tests/test_t1_clearance.py` checks actual capsule/convex surface distances,
the 5 mm threshold, bounding-box false positives and unresolved queries.

## Eight-check completion validator

`evaluation/validate_t1.py` implements the researcher's completion checklist. Run
it **inside an approved Isaac Lab container**, with the inspected `T1_IMAGE_ID`
and allocated `ISAAC_GPU_UUID` already set. Its output must be a new directory on
a writable persistent mount:

```bash
/isaac-sim/python.sh /workspace/evaluation/validate_t1.py \
  --out /t1-run/validation --device cuda:0
```

This runs a **30 simulated-second** nominal PD hold, target preparation, an
isolated FK/fault/IK-path worker and two scripted IK evaluation suites. The worker
also regenerates targets with seed 1101 from the same reference snapshot to test
sampling reproducibility. The two dynamics runs use the exact same frozen target
file. Each subprocess has a 30-minute wall limit; generation and repeated suites
may be substantially longer than the short smoke test. The script starts no
Docker containers and performs no training or asset repair.

The validator writes:

| File | Contents |
| --- | --- |
| `validation_report.json` | Eight named checks, PASS/FAIL/BLOCKED/NOT_RUN, progress, child exit status/log paths, artifact hashes and overall verdict |
| `targets.json` | Frozen resolved targets; written only after successful preparation, never a fabricated placeholder |
| `trajectories.csv` | Per-step world-frame reference and actual EE poses, phase/time and trial identifiers |
| `metrics.csv` | Errors, base pose/velocity/height/tilt, foot contacts/drift, wheel motion and failure flags |
| `config.yaml` | Seed, controller, simulator timing, proposed tolerances, image/GPU identity, loaded robot/actuator parameters, source hashes and full-config reference |
| `trial_summary.csv` | Steady-state summaries, tagged by repetition |

CSV vector/quaternion fields contain JSON arrays; quaternions use `wxyz`.
`stage`, `repetition`, `target_id`, `env_id` and `episode_time_s` join trajectories
and metrics. Fault rows additionally name `validation_case`. All phases and
partial traces are retained. `runs/` preserves original step/summary/config files,
commands, stdout/stderr, process outcomes and worker evidence. `source/` preserves
the validator, worker, evaluator, task modules and protocol.

The eight checks cover the 22-joint B2W mapping/TCP/loaded gains and finite,
compliant 30 s hold; simulator FK and command-frame invariance; known synthetic
errors; 24 fixed targets and 9 circles with independent recorded-path checks;
standing diagnostics and isolated faults; repeated targets/configs/traces; and
independently recomputed pose errors, reference poses and steady-state summaries.
Fault testing uses a separate kinematic cube for a **physical arm collision**,
a cached-state NaN injection that is never sent to PhysX, independent tilt/height
injections, and a normal timeout with a surviving second environment.

**Proposed, recorded numerical tolerances:** repeated distances `1e-4 m`, angles
`1e-4 rad`, references/target definitions `1e-9` in their stored units, exported
error recomputation `1e-8`, FK `1e-3 m` / `1e-2 rad`. Repetition clocks and failure,
contact and stance flags must match exactly. The 30 s hold additionally requires
the existing standing-compliance diagnostic to remain clear after 2 s settling;
this does not change the task's diagnostic-only stance termination setting.
These are validation tolerances, not tracking-accuracy targets. They are not
relaxed automatically. Path checks remain discrete. OBBs select candidates;
physical surfaces decide clearance, with a recorded `1e-8 m` numerical tolerance.

`PASS` and exit **0** require **8/8** checks and all required artifacts. Missing,
blocked or failed checks produce a nonzero exit and an incomplete/failed report.
A native crash invalidates runtime evidence even if the worker wrote passing
assertions before shutdown. Known asset overlaps and shutdown failures are not
bypassed. Full runtime execution of this new harness remains **unverified**.

For a safe host-only check:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 evaluation/validate_t1.py \
  --cpu-only --out /tmp/t1-validation-cpu-UNIQUE
```

This deliberately exits **1** with `INCOMPLETE (1/8)`: only synthetic metrics are
executed. It writes config/report/CSV schemas and leaves `targets.json` absent.
The report plumbing and analysis functions are tested with
`tests/test_validate_t1.py`; stubbed-worker fixtures are not simulator results.
Implementation verification after the physical-surface update: **64 host CPU
tests passed, seven USD SDK tests skipped on the host**; those **seven passed**
separately using the existing image's CPU-only USD SDK. This includes 20 validator
tests. No full eight-check Isaac validation run was performed.

## Simulator entrypoints — authorization required before launching

Use the configured Isaac Lab image and an allocated GPU UUID, after checking
image identity, dependencies, robot assets, mounts and output/cache permissions.
Use a unique container name and project-specific persistent paths. `AGENTS.md`
§8.3 requires permission before Docker/GPU workloads. Authorized collision and
standing diagnostics are reported below; they do not complete the eight checks.

The commands below run **inside an approved container**. They do not create one.
Set `T1_IMAGE_ID` to the inspected image ID and `ISAAC_GPU_UUID` to the allocated
GPU's UUID in that container's environment. These are required provenance inputs;
optionally set `T1_IMAGE_TAG` to retain the human-readable image tag as well.
the evaluator does not discover/reserve a GPU or start Docker. `--out` must be a
new path on a persistent mount. Capture the process's stdout/stderr externally as
well, including native simulator messages. For example, with the parent directory
already created and writable by the container user:

```bash
/isaac-sim/python.sh /workspace/evaluation/eval_t1.py \
  --mode smoke --controller hold \
  --out /workspace/repos/robot_lab/logs/t1/smoke-UNIQUE \
  > /workspace/repos/robot_lab/logs/t1/smoke-UNIQUE.stdout.log 2>&1
```

Smoke mode runs six simulated seconds on one environment without targets. It
does not require a checkpoint or certify tracking performance. It must succeed
before preparing targets:

```bash
/isaac-sim/python.sh /workspace/evaluation/eval_t1.py \
  --mode prepare \
  --out /workspace/repos/robot_lab/logs/t1/prepare-UNIQUE \
  > /workspace/repos/robot_lab/logs/t1/prepare-UNIQUE.stdout.log 2>&1
```

Preparation settles one environment for 2 s, checks finite/stable nominal state
and independent USD FK against measured simulator frames, then runs CPU
IK/geometry checks. It may take substantially longer than the simulated settling
time. If 24 fixed and nine complete circles cannot be accepted, it writes the
rejection audit and fails. Counts/radius/limits are never silently relaxed.
There is no pre-generated or runtime-validated manifest in this change.

Evaluate that exact manifest with one vectorized instance per target:

```bash
/isaac-sim/python.sh /workspace/evaluation/eval_t1.py \
  --mode evaluate --controller ik \
  --manifest /workspace/repos/robot_lab/logs/t1/prepare-UNIQUE/targets.json \
  --out /workspace/repos/robot_lab/logs/t1/evaluate-UNIQUE \
  > /workspace/repos/robot_lab/logs/t1/evaluate-UNIQUE.stdout.log 2>&1
```

`hold` is a negative-control instrument. `ik` uses measured pose/Jacobian with a
bounded integrated arm target; `joint_path` replays the audited arm path, ramping
fixed-target joints over 2 s. All three hold nominal leg targets; the environment
still exposes all leg actions for future whole-body controllers. These scripted
controllers are not learned or model-free baselines. IK target memory is
recoverable from commanded offsets/applied targets in the logs.

## Pending runtime acceptance and supervisor decisions

**Current update, 2026-11-09, draft.2:** the existing USD is authoritative. Assets,
collision exclusions and filtering are unchanged. Bounds only select candidates;
analytic capsule distances and certified capsule/convex distances classify actual
penetration, positive clearance below 5 mm and harmless bounding-box overlap.
Links without physical colliders (link01/link05) acquire no invented visual
colliders. Unavailable cooked mesh geometry is explicitly unresolved.

The link00/link02 capsules really overlap by approximately **12.5 mm**. Both
filtered contact views recorded **zero contacts and zero normal/friction forces**
at every physics tick. The existing articulation disables self-collision; this
does not exempt the pair from the separate geometric safety check. Additional
capsule overlaps and genuine bounding-box false positives are documented in
[the collision and standing report](T1_COLLISIONS_2026-11-09.md).

The separate `diagnose_t1_standing.py` diagnostic recorded **30 simulated seconds,
6,000 finite physics samples and 1,500 control samples**, with no resets, fall or
physical-stop condition. Standing-compliance diagnostics were clear after 2 s.
It deliberately observes dynamics despite the logged geometric failures; it
does not relax production terminations or constitute a full T1 pass. Cleanup
hung after data collection and required stopping only its own container (exit
137). Two earlier 1 s diagnostics crashed during native teardown. A clean
simulator exit remains unresolved.

Eight mesh colliders did not yield PhysX cooked geometry. None was a narrow-phase
candidate in the recorded nominal trajectory; future candidate queries remain
unresolved until the actual representation can be obtained. No raw/visual mesh
or bounding box is substituted to manufacture a verdict.

The earlier [smoke](T1_SMOKE_2026-11-08.md) and
[review](T1_REVIEW_2026-11-09.md) reports are historical. Their visual-bound
fallback and cylinder-repair direction are superseded. No replacement geometry
